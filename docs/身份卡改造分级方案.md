# 身份卡改造分级方案

状态：**未开工**。2026-11-11 记录，等使用者说「开始」再动。

来源：对 `op7418/dsh-guizang-design` 实体设计做的对照分析。可移植的三条是「实体带时间」「实体带动作」「序列只在续期型卡上有意义」，视觉与 skill 机制不在范围内。

## L1 数据与文案（半天，可随时回滚）

| 项 | 改动 | 判据 | 回滚 |
|---|---|---|---|
| 卡老化 | front-matter 加 `updatedAt`；`audit` 报最久没动的三张 | `audit` 输出含「最久未动」；缺这个字段的老卡不报错 | 删字段 |
| 交接 | front-matter 加 `handoff: [review]`；`use`/`switch` 收尾输出一句带路径的提示 | 切到 review 时不用使用者再说审什么 | 删字段 |
| 沿用 | 新 action `repeat`：复用上次认领的卡与 verify | 新会话 `repeat` 后 `current` 显示卡与验收命令 | 删 action |
| 措辞 | `library report` 返回值统一为「已登记」 | selftest 断言字符串 | 改回一行 |

## L2 一个子系统（一到两天）

| 项 | 改动 | 判据 | 回滚 |
|---|---|---|---|
| series | `series/<名字>/` 目录约定 + `identity series next` | 第 N 份能列出上一份的样本与增量判据 | 删目录；`collect()` 不递归，不受影响 |
| 使用记录 | `.usage.jsonl` 追加（卡 id / 会话 / 起止 / 产物 / 验收）+ `identity usage <id>` | 能按时间列出某张卡的使用 | 删文件，claims 不动 |
| skill 通道 | 注册到 `ctx.skills`，`config.skills` 开关 | skills 能列出卡；`ctx.skills` 缺失时 `use` 照常可用 | 关开关 |

## L3 跨出提示词层（一周以上）

| 项 | 改动 | 判据 | 回滚 |
|---|---|---|---|
| recall | 按 seq 或关键词从会话日志取回片段 | 实测命中率与多出来的往返 | 删工具 |
| 只读侧栏页 | webServer 前缀路由 + client + 静态资源 | 只有 GET，无写接口 | 删路由与资源 |

## L4 明确不做

作品库与缩略图、recipes 编排、语气档案、请求级挑选、改 surface 模型。这几样的成本在长期维护，服务的是产出物管理，不是「用哪种方式干活」。

## 顺序

L1 全做。L2 只做 series，`lab-report` 受益最直接；使用记录与 skill 通道等 L1 稳定后再说。L3 先做 recall 原型量数字，别直接上；侧栏页会破掉单文件零依赖，除非真嫌 `identity list` 难看。

## 停止条件

写死，触到就停：

- `audit` 报卡老化两周没人看 → L2 停。
- series 用了三次还在手工建目录 → 砍掉。
- recall 让对话明显变慢 → 砍掉。

## 需要先定的两件事

- `code` / `lab-report` 的样本节要不要跟着改（series 依赖它）。
- 接不接受 `~/.dsh/cards` 下多一层 `series/` 目录。
