# 审查请求模板

复制下面这块填满，发给一个**新对话**（不要发给执行任务的对话——它会替自己的成果辩护）。

```
审查请求

对象：<被审文件/目录的绝对路径>
层：full | quick
判据：<任务书/规范的路径>        ← 只审这里要求的，不按通用规范增补
材料：
  必读：<路径> …
  参考：<路径> …（只在判据涉及这块时才读，不要通读）
  禁用：<路径> …（执行者的计划、草稿、.collab/、_tmp/）
多方：允许 | 不允许                ← 允许时审查员会加载 codex-review 技能
产出：一份审查报告；不修改任何文件
```

## 三栏怎么填

**层**

| 层 | 查什么 | 用在哪 |
|---|---|---|
| `quick` | 只查机械一致性：占位符、章节结构、图表编号、字数下限 | 交付前自查 |
| `full` | 四层完整：需求符合度 → 图文对应 → 图形规范 → 版式格式 | 独立审查 |

**材料**

| 栏 | 判据 |
|---|---|
| 必读 | 不读就判不了（被审对象、判据本身、核心图） |
| 参考 | 只在判据涉及那一块时才读（往期成果查编号、课件查口径） |
| 禁用 | 读了会被带偏（执行者的思路文档） |

**禁用的理由**：审查要看的是"结果对不对"，不是"思路顺不顺"。读了执行者的计划，就会不自觉地替它辩护。

## 一个填好的例子

```
审查请求

对象：C:\Users\yu050\Desktop\大三上\软件工程\详细设计\1014230220_于环宇_详细设计说明书.docx
层：full
判据：C:\Users\yu050\Desktop\大三上\软件工程\详细设计\详细设计要求.docx
材料：
  必读：上面两份；figures\ 下 10 张 PNG；figures\drawio\*.drawio
  参考：前三次成果（核编号与取值）；课程\06章 详细设计.pdf（核评分口径）；7.1/7.2/8.1/8.2 转写
  禁用：00_预测与依据.md、01~06_*.md、figures\绘图说明.md、.collab\、_tmp\
多方：允许（std 档）
产出：一份审查报告；不修改任何文件
```

## 审查员会按这个返回

1. **结论**：`pass` / `pass_with_comments` / `needs_work`（硬判定：有 blocker 就是 needs_work）
2. **三张表**：需求符合度 / 问题清单 / 图文对应
3. **两段**：必须改的、建议改的

## 拿到报告之后

**回原对话改**，不要在这个审查对话里改——换了对话改，等于重建一遍思路。

除了一种情况：**blocker 级问题且你已经确认要修**，这时可以在审查对话里直接动手（但也就失去了"独立"的立场，报告到此为止）。
